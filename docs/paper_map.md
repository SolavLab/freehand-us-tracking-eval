# Where each published number comes from

Every table, figure and quoted figure in the manuscript, mapped to the command
that produces it. Written from an actual generated tree, not from intent.

```bash
vipose evaluate --out results/paper     # ~4 min, the shipped 15 MiB only
vipose tables   --store results/paper --out tables
vipose figures  --store results/paper --out figures
```

Everything below needs only that. No raw recordings, no GPU, no container.

## Tables

| Manuscript | Generated by | Output | Status |
|---|---|---|---|
| Table 2 — motion characteristics | `vipose tables` | `tables/motion.tex` | **identical**, 32/32 numeric tokens |
| Table 3 — hand–eye residuals | `vipose tables` | `tables/residuals.tex` | **identical**, 84/84 numeric tokens |
| Vicon rigid-body residuals | `vipose tables` | `tables/reference_fit.tex` | **does not match exactly** — see below |

The two `.tex` files are the table *body* — the rows between `\midrule` and
`\bottomrule` — so they diff directly against the manuscript:

```bash
diff <(sed -n '/\\label{tab:residuals}/,/\\bottomrule/p' results.tex | sed '1,/midrule/d') \
     tables/residuals.tex
```

## Figures

| Manuscript | Generated by | Output |
|---|---|---|
| Figure 3 — error distributions | `plot_combined_metrics_violin.py` (see gaps) | — |
| Appendix A, angular-speed overlay | `vipose figures` | `figures/sync_omega_overlay.png` |
| Appendix A, stage-3 objective | `vipose figures` | `figures/sync_stage3_objective.png` |

Both appendix figures match the published PNGs to a mean absolute pixel
difference under 1/255 on an identical canvas. They are not compared
pixel-for-pixel in the test suite, because matplotlib is not byte-reproducible
across versions; the tests check geometry and the properties the figures exist
to show.

## Quoted figures in the prose

| Claim | Value | Source |
|---|---|---|
| Calibration floor, `‖t_M_C‖` spread across conditions | 6.32 / 4.28 / 2.77 mm | `results/*/cells/*/calibration.json` → `camera_to_marker_distance_mm`; **reproduces exactly** |
| Calibration well-posedness, `1 − σ₂` | 0.029–0.044 | `tables/motion.json` → `shah_margin`; **reproduces exactly** |
| Stage-3 offset correction | up to 11.8 ms (ZED-SDK), <3 ms (cuVSLAM) | `results/*/recordings/*/window.json` → `offset_refinement_stages.stage3_delta_ms` |
| Repeated poses per pipeline | 54 / 0 / 40 | `vipose.io.tracks.Track.repeated_poses()` |
| Poses not returned | 2 / 192 / 0 | `Track.omitted_frames()` |
| Trial-to-trial repeatability | 0.05–0.94 mm, 0.019–0.037° | difference between the two pivot rows of `tables/residuals.json` |

The two pose-continuity measures need care and the code documents why: omissions
are counted from the **timestamps**, as `round(dt / median(dt)) − 1`, not from
the frame column, because cuVSLAM renumbers its output sequentially so a dropped
input frame leaves no gap. A repeated pose is exact equality of all six
components with the previous row.

## Known gaps

**The Vicon rigid-body residual table does not regenerate exactly.** The
published values are reproduced to about 0.02 mm but not to the printed
precision, and the exact definition behind them is not pinned down:

| Recording | published | native 240 Hz | resampled (zed-sdk / zed-cuvslam / rs-cuvslam) |
|---|---|---|---|
| Pivot | 0.279 ± 0.088 | 0.244 ± 0.073 | 0.273 / 0.260 / 0.278 |
| Freehand | 0.231 ± 0.066 | 0.220 ± 0.054 | 0.241 / 0.231 / 0.222 |
| Mixed | 0.209 ± 0.058 | 0.237 ± 0.049 | 0.213 / 0.214 / 0.200 |
| Pivot (repeat) | 0.265 ± 0.067 | 0.319 ± 0.068 | 0.267 / 0.266 / 0.277 |

`reference_fit.tex` emits the **native** figure, because a table characterising
the motion-capture system should not depend on which camera's clock the
reference happened to be resampled onto. The published values sit among the
resampled ones instead, but match no single pipeline, so the grid they were
computed on is not identified. Nothing else depends on this: the table is
context for the reference's own uncertainty, and the 0.28 mm figure the paper
uses as an interpretation floor is unaffected at the precision it is quoted.

**Figure 3 has no generator in this repository.** It is still produced by
`plot_combined_metrics_violin.py` in the original tree, which reads the legacy
`*_angles.csv` / `*_distances.csv` layout. Porting it is straightforward — the
data is `tables/residuals.json` — but it has not been done.

**Two claims have no generator here.** The residual autocorrelation time
(τ = 0.7–2.9 s) and effective sample size (N_eff = 16–92) in Appendix A come
from an investigation script that has not been ported. The numbers are recorded
in the manuscript and were verified when written, but this repository does not
regenerate them.

## What is checked automatically

`pytest` enforces the mapping above rather than trusting this document:

- every cell reproduces its Table 3 row at the printed precision, and the
  per-frame series match the golden master elementwise
- every recording reproduces its Table 2 row, including the Shah margin
- the calibration floor reproduces to 0.02 mm
- the emitted LaTeX has the manuscript's row order, column count and rules
- the pose-continuity counts reproduce the window-independent published values
- no numerical module imports pyplot, so results never depend on drawing

If this document and the code disagree, the tests are the ones that will notice.
